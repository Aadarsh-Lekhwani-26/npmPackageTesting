Active Server Rehash Policy

needsRehash() Rule

When a user authenticates, the server runs needsRehash(storedHash, activePolicy). If the stored hash uses lower cost parameters than this policy, it is automatically recomputed with the upgraded parameters.

    05

    Argon2id Architecture & Parameter Roles

    How Argon2id (RFC 9106) defeats password cracking attacks and why parameter tuning matters.

    🧠

    Memory Cost ($m$)

    Memory Hardness & ASIC Resistance

    Defines the total size of the internal 2D memory block matrix in KiB ($8 \times p \le m \le 2\text{ GiB}$). Because each block lookup requires accessing high-speed RAM, brute-force attackers using GPUs or custom ASICs cannot parallelize attacks without incurring massive physical memory costs.

    ⏱️

    Time Cost ($t$)

    Sequential Iterations

    Specifies the number of full passes over the memory matrix ($t \ge 1$). Each pass applies the 64-bit non-linear BlaMka permutation (Function $G$) to mix blocks with previous lanes, multiplying the time needed for offline password guesses.

    🔀

    Parallelism ($p$)

    Independent Execution Lanes

    Splits the memory matrix into $p$ independent horizontal lanes ($1 \le p \le 2^{24}-1$). Allows multi-core authentication servers to divide memory across hardware threads while synchronizing at 4 slice boundaries per pass.

    🛡️

    Argon2id Hybrid Scheme

    Best-of-Both-Worlds Defense

    Combines Argon2i (data-independent addressing in the first slice to eliminate cache-timing side-channel leaks) and Argon2d (data-dependent addressing in subsequent slices to maximize GPU/ASIC trade-off resistance). Recommended by RFC 9106 and OWASP.
